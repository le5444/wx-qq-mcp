# 身份、媒体关联与完整性规则

本项目只能检查本地数据中的账号和记录标识，不代替用户确认某个账号在现实中属于谁。微信与QQ的同名联系人不会自动绑定成一个人。

## 读取身份

- QQ发现接口允许名称和关键词检索，但实际读取明确UID/UIN时要求精确命中。名称读取也要求完整、精确且唯一；候选被截断时不建立唯一性。缺失UID不退化成对UID列查询数字账号并报告零条。
- 本人身份只能由明确账号资料精确验证；本人资料缺失或UID/UIN矛盾时标记未知，随后资料恢复可重新验证。查询本人的会话不等于读取所有本人发出的私聊。
- `contact`、`chat`、`group`等选择器互相矛盾时拒绝，不从不同参数拼出另一个查询。发送者的UID、UIN、昵称和方向也分别匹配。
- 原生QQ统计使用稳定ID作为机器键，展示名只是标签。统一统计按发送者ID计数，冲突项归入未知并标明不确定性。微信无发送者ID的系统记录方向为`system`，不充作对方发言。
- QQ数字号码与UID只能经已验证的账号映射互认；不能用名字作为别名证据。统一时间线在连续分页时固定规范身份。

## 失败与完整性

完整读取一页后先校验所有记录，再返回结果。错误会话不通过`available_source_pages`等诊断字段返回正文。直接微信读取中明确`talker`的请求同样核对显式会话字段。

分页结束只证明当前可用查询到达终点。辅助来源失败时，精确查询不能断言目标不存在，群统计不能宣称完整；来源告警、分页终点和身份不确定性分别保留。可选OCR失败不应让已读文字被当成读取失败。

## 媒体关联

当前记录的`original`与外层身份必须一致，外层可以补缺失字段，不能覆盖矛盾。语音只取当前消息允许的资源字段，不遍历引用消息。扫描共享音频缓存需要聊天、服务器ID、本地ID和时间；多个不同内容的同身份候选明确拒绝。

微信媒体侧元数据缺乏完整会话与消息身份时不加入共享关联索引。QQ同一变体的同名缓存若内容冲突则拒绝；普通文件名不用于跨月份猜测。原图与缩略图可以字节不同。文件名一致和像素可解码仍不是对图片语义或现实来源的独立证明。

外部`--qq-enriched`或阅读页更新文件只能补派生媒体/OCR/转写，不能替换原消息身份、发送者或正文。仅凭native消息号不跨聊天关联。正确的精确记录补丁兼容派生字段缺省，但显式身份矛盾会拒绝。

导出遇到基础记录ID冲突时，为相关记录附内容摘要以消歧。查询该完整ID需摘要匹配；只传原生ID遇到多个候选仍返回歧义。若原始历史已经变化，摘要不再匹配时不会随意选择旧ID下的新记录。

## 验证边界

回归使用合成SQLite、图片、音频文件和外部读取器替身，测试错误归属条件和正确输入。真实本机验收另行执行且不进入公开夹具。通过这些用例不保证所有微信/QQ版本、被迁移数据或未知媒体格式都兼容；尚未同步或丢失的内容仍不可凭空恢复。
